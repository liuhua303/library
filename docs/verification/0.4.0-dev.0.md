在 M 系列 Mac 上安装原生 arm64 Node.js 24，解压后进入包含 `package.json` 的目录：

```bash
npm ci
npm run dev
```

源码试运行后，可执行 `npm run dist:mac:local` 制作本机 ad-hoc 试用包；正式分发使用 `npm run dist:mac`，需要 Developer ID 签名和 Apple 公证配置。输出目录与完整操作流程集中维护在[开发说明](../development.md#mac-准备与打包)。这些命令尚未在 Mac 上执行。

### 首次上传及锁文件修复

源码及工作流已首次提交并推送到默认分支 `main`，提交为 `d12d6cc62d8d1fe2dda58ddac7c0ae3f39556774`。[第一轮云端运行](https://github.com/liuhua303/library/actions/runs/46030918417)已实际启动，确认环境为 `darwin/arm64`、Node.js 24.22.3、npm 11.19.1；在 `npm ci` 阶段失败，没有构建 DMG。[失败摘录](./evidence/0.4.0-dev.0/2026-11-28/cloud-attempt-1.json)已保留。

原因是锁文件中的可选 WASM 构建依赖声明了 `@emnapi/core` 和 `@emnapi/runtime` 的 `2.0.0-beta.2`，却缺少这两个包的完整记录。已依据 npm 官方 registry 的对应版本元数据补齐 tarball、完整性摘要及依赖，未改变任何已有包节点、版本或完整性摘要。`npm.cmd ci --dry-run --ignore-scripts --os=darwin --cpu=arm64 --offline --no-audit --no-fund` 在 Windows 上的依赖规划检查通过；它不安装 Mac 运行时，也不代替云端实际安装。

### 第二轮及 plist 兼容修复

[第二轮云端运行](https://github.com/liuhua303/library/actions/runs/46031701353)对应提交 `d42cb2b53235a6984f506a4ec357a6bc92a36535`。实际依赖安装、114 项单元测试、TypeScript 与生产资源构建通过，但 Mac 打包读取 plist 时失败。[失败摘录](./evidence/0.4.0-dev.0/2026-11-28/cloud-attempt-2.json)已保留，没有可交付 DMG。

根因是原有全局 xmldom 覆盖使 `plist@3.1.0` 使用了要求 MIME 参数的 0.9 分支，而 plist 调用未传此参数。已改为按使用方覆盖：EPUB.js 继续使用 0.9.12，构建链的 plist 使用兼容的安全修补版 0.8.15；没有修改第三方源码。另修复构建错误退出方式，并要求返回的 DMG 文件实际存在，避免 electron-builder 的清理逻辑将失败误报为成功。

新增直接用构建链 plist 解析签名权限文件的回归检查；修复后 Windows 本次新运行 115 项单元测试与 `npm.cmd run build` 通过。Mac 命令在 Windows 上仍按预期以退出码 1 拒绝执行。旧 npm 在 Windows 重新计算锁文件会再次漏掉上述可选 WASM 节点，因此本次保留它们的完整记录，实际干净安装以云端 `npm ci` 结果为准。
