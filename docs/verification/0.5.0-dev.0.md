## 本次 Windows 源码构建验证

环境：Windows 11 x64、Node.js 24.12.0、Electron 45.5.0；源码应用版本 `0.5.0-dev.0`。开发构建由 Electron 可执行程序加载 `app/main.cjs`，其 `app.getVersion()` 返回 Electron 版本；不能据此把开发运行当成安装包检查。

| 实际命令 | 本轮结果 |
| --- | --- |
| `npm.cmd test -- --reporter=default --reporter=json --outputFile=artifacts/japanese-unit-results.json` | 11 个测试文件、162 项测试通过 |
| `npm.cmd run build` | TypeScript、Vite 和主进程构建通过；Vite 保留现有 bundle 大小提示 |
| `npm.cmd run test:e2e` | 八套桌面回归全部通过，使用本轮生产构建 |
| `node scripts/japanese-smoke.mjs` | 日语流程通过；随后增加并运行 Quiet 日语读音可读性检查，六组检查均通过 |

八套桌面脚本覆盖英文基础收录与解析、点击与回跳、原书颜色覆盖、选区几何及跨页调整、书架与浮层、六主题和书签、沉浸阅读，以及新增日语流程。日语实际用鼠标点击无空格文本末字右侧，拖选含 ruby 的整句，检查中文义、假名及日文例句、仅中文整句翻译、标记查看与回跳、语言切换保留原释义、重启语言与位置持久化，再导入英文书验证原英文解释字段。Quiet 日语读音使用主题实色，未发现白底浅字、透明淡化或模糊滤镜。

单元检查还覆盖语言元数据和正文探测、误标及混排、旧数据库幂等迁移、已有解析与排队任务语言快照、英日词条隔离、原文活用及位置校验，并通过英文提示词指纹和请求结构检查确认原英文路径保持。语言保存失败不会被后续位置写入或关闭重试偷偷应用。

本轮调试修正了日语词尾 caret 边界命中，并将新增脚本的异步 IPC 等待改为显式轮询已完成的数据，避免把 Promise 本身当成条件已满足。最终结果为重新运行所得，不把调试失败结果作为通过证据。
