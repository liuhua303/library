# 0.5.0-dev.1 旧日文书语言恢复验证记录

## 问题与修复

日期：2026-11-28，Asia/Shanghai。用户报告导入日文书后，多项解析提示“缺少有效的英文解释”。只读检查当前应用数据确认，该书保留了旧版的 `en/legacy` 记录；原 EPUB 主语言为 `ja`，本版检测器实际返回 `ja/metadata`。旧版重复导入相同 hash 会直接返回旧书记录，没有采用新的语言识别结果，失败任务也继续保留旧英语快照。

修复启动时旧书语言升级和重复导入的合并；仅更新符合条件的自动语言来源，保留手动选择、阅读位置、字号、主题、书籍身份及已完成释义。旧失败项由用户点击“重新解析”后，从原 CFI 重建当前语言的选文、上下文和偏移，再整体替换失败任务，避免只改语言造成 ruby 定位错位。不会自动重译已完成项或自动重新请求模型。具体当前规则见[需求](../requirements.md#旧书语言修正与失败重试)与[开发说明](../development.md#语言识别与解析隔离)。

本轮继续在 `codex/japanese-support` 分支，基于提交 `49ba7c46bb2a6a55c4f18aac36a242ebdbd6823d`；本机检查时修复代码和文档尚未提交。`main` 保留用户已检查的 0.4.0-dev.1。本轮为用户反馈问题的实现与自动验证，不记为用户已验收修复。

新增桌面脚本使用自编 EPUB，在隔离书架中构造升级前的英语语言记录、两个解析失败项及一个已完成项。实际通过界面点击“重新解析”，验证：

- 启动识别为日语，已完成释义和旧任务先保持，不自动发起重新解析。
- 原失败词语在 ruby 之后，重试后偏移整体正确重建，显示中文义与假名，不要求英文解释。
- 跨 ruby 的原失败整句去除注音后按日语整句处理，只保留中文翻译；仍能返回原文。
- 收藏 ID、时间和原 CFI 保留，已完成项未被改写，两个手动重试仅发起两个模拟日语请求。

单元测试覆盖同 hash 重新识别、可靠来源和手动选择保护、启动缺文件/损坏档案隔离、旧完成和排队记录保留、失败任务整体替换及计数重置、跨书或跨 CFI 替换拒绝，以及已完成和正在处理任务的保护。原英文提示词与请求格式回归继续通过。

## 使用与未验证范围

当前开发主进程需要关闭旧窗口后重新执行 `npm run dev` 才加载修复。旧日文书不必删除再导入；打开后检查“主题与设置 → 书籍语言”为日语，再对失败项点击“重新解析”。仍然无法确定或曾手动选错语言时，可在该处选择正确语言。

本轮没有改写用户日常数据库、没有触发用户真实失败任务或调用付费 DeepSeek API，也没有将用户书籍或词条内容加入仓库。真实模型质量、用户本机重启后的修复体验、Windows 安装向导和覆盖安装、Mac DMG 安装及原生交互尚未验收。固定版式和竖排适配仍不在本轮范围，分支尚未合并进 `main`。
